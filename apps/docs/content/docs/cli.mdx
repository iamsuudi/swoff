# CLI Reference

Swoff provides a command-line interface for easy project setup and management. The CLI helps you initialize, generate, validate, and manage Swoff in your projects.

## Installation

### Quick Start (Recommended)

Use `npx` to run the CLI without installation:

```npm
npx @swoff/cli init
```

### Manual Installation

Install as a dev dependency in your project:

```npm
npm install -D @swoff/cli
```

After installation, you can run the CLI directly:

```npm
npx @swoff/cli init
npx @swoff/cli validate
npx @swoff/cli generate
```

## Commands

### init

Initialize Swoff in the current directory. Creates a `swoff.config.json` with sensible defaults and a `swoff/` directory.

```npm
npx @swoff/cli init
```

**Options:**

- `--framework <name>` - Initialize with framework-specific defaults

**Frameworks:**

- `react-vite` - React with Vite
- `nextjs` - Next.js
- `vue-vite` - Vue with Vite

**Examples:**

```bash
# Basic initialization
npx @swoff/cli init

# Initialize with React + Vite defaults
npx @swoff/cli init --framework react-vite

# Initialize with Next.js defaults
npx @swoff/cli init --framework nextjs
```

This command:

1. Creates `swoff.config.json` with default configuration
2. Creates `swoff/` directory for generated files

**Next steps after init:**

```bash
# 1. Review and customize config
nano swoff.config.json

# 2. Validate configuration
npx @swoff/cli validate

# 3. Generate all files
npx @swoff/cli generate
```

### generate

Generate service worker and/or supporting files based on your configuration.

```bash
npx @swoff/cli generate
```

**Options:**

- `--sw-only` - Generate only the service worker
- `--files-only` - Generate only supporting files

**Examples:**

```bash
# Generate both service worker and files
npx @swoff/cli generate

# Generate only service worker
npx @swoff/cli generate --sw-only

# Generate only supporting files
npx @swoff/cli generate --files-only
```

**Generated files:**

| File                         | Feature Flag                        | Description                       |
| ---------------------------- | ----------------------------------- | --------------------------------- |
| `swoff/sw-template.js`       | always                              | SW template with placeholders     |
| `swoff/sw-injector.js`       | `clientRegistration`                | Client-side SW registration       |
| `swoff/fetch-wrapper.js`     | always                              | Fetch with cache strategy headers |
| `swoff/cache.js`             | `tagInvalidation` or `crossTabSync` | Cache tag invalidation            |
| `swoff/invalidation-tags.js` | `tagInvalidation`                   | URL-to-tag generation helper      |
| `swoff/store.js`             | `mutationQueue`                     | IndexedDB CRUD operations         |
| `swoff/reconcile.js`         | `mutationQueue`                     | ID reconciliation after sync      |
| `swoff/mutation-queue.js`    | `mutationQueue`                     | Offline mutation queue            |
| `swoff/background-sync.js`   | `backgroundSync`                    | Background Sync API wrapper       |
| `swoff/indexeddb.js`         | `indexeddb`                         | DB setup with migrations          |
| `swoff/pwa-install.js`       | `pwa`                               | PWA install prompt handler        |
| `swoff/sw-generator.js`      | always                              | Build script for versioned SW     |
| `swoff/swoff.d.ts`           | always (TS projects)                | TypeScript declarations           |
| `public/manifest.json`       | `pwa`                               | Web app manifest                  |

**After generation, integrate into your app:**

```javascript
// In your app entry point (e.g., main.tsx, app.js)
import { initServiceWorker, shouldRegisterSW } from "./swoff/sw-injector.js";

if (shouldRegisterSW()) {
  initServiceWorker();
}
```

### validate

Validate your `swoff.config.json` against the schema.

```bash
npx @swoff/cli validate
```

**What it checks:**

- Required fields are present (`enabled`, `version`, `serviceWorker`, `features`, `build`)
- `serviceWorker.autoRegister` and `autoUpdate` are booleans
- `defaultStrategy` is one of the 5 valid strategies
- All feature flags are known and boolean
- `version` is `"from-package"` or valid semver
- `minSupportedVersion` is valid semver
- `build.outputDir` and `swFilename` are strings
- `pwa.preventDefaultInstall` is boolean
- `database.name` matches pattern `^[a-zA-Z0-9-_]+$`
- `database.stores` is an array of valid names

**Example output:**

```
Validating swoff.config.json...
✅ Configuration is valid!

Config summary:
  Version: from-package
  Default strategy: cache-first
  Features enabled: versionedSw, offlineReads, pwa, crossTabSync, tagInvalidation, clientRegistration
```

### add

Add a specific feature to your configuration and regenerate files.

```bash
npx @swoff/cli add <feature>
```

**Available Features:**

| Feature            | Flag Enabled      |
| ------------------ | ----------------- |
| `offline`          | `offlineReads`    |
| `mutation-queue`   | `mutationQueue`   |
| `pwa`              | `pwa`             |
| `cross-tab`        | `crossTabSync`    |
| `auth`             | `auth`            |
| `tag-invalidation` | `tagInvalidation` |
| `background-sync`  | `backgroundSync`  |
| `indexeddb`        | `indexeddb`       |

**Examples:**

```bash
# Add offline feature
npx @swoff/cli add offline

# Add mutation queue
npx @swoff/cli add mutation-queue

# Add PWA components
npx @swoff/cli add pwa

# Add tag-based cache invalidation
npx @swoff/cli add tag-invalidation
```

### clean

Remove old versioned service worker files from the output directory, keeping only the current version.

```bash
npx @swoff/cli clean
```

**Behavior:**

- Reads the current version from `dist/version.json`
- Finds all files matching `sw-v*.js` pattern
- Deletes files that don't match the current version
- Reports what was deleted

**Example output:**

```
Cleaning Old Service Worker Files
=================================
Deleted: dist/sw-v0.9.0.js
Deleted: dist/sw-v0.8.0.js
✅ Cleaned 2 old service worker file(s).
```

Show help information for commands.

```bash
# Show all commands
npx @swoff/cli help

# Show specific command help
npx @swoff/cli help init
npx @swoff/cli help generate
npx @swoff/cli help info
```

## Common Workflows

### New Project Setup

```bash
# 1. Initialize Swoff
npx @swoff/cli init --framework react-vite

# 2. Review and customize config
nano swoff.config.json

# 3. Validate configuration
npx @swoff/cli validate

# 4. Generate files
npx @swoff/cli generate

# 5. Check what was generated
npx @swoff/cli info
```

### Incremental Feature Addition

```bash
# Start with basic setup
npx @swoff/cli init

# Add features one at a time
npx @swoff/cli add offline
npx @swoff/cli add mutation-queue
npx @swoff/cli add pwa
npx @swoff/cli add tag-invalidation

# Generate after each change (or once at the end)
npx @swoff/cli generate
```

### Configuration Iteration

```bash
# Edit your config
nano swoff.config.json

# Validate before generating
npx @swoff/cli validate

# Regenerate files
npx @swoff/cli generate

# Review what changed
npx @swoff/cli info
```

### Cleanup Old SW Files

```bash
# After deploying a new version, clean up old SW files
npx @swoff/cli clean
```

## Configuration File

The CLI expects `swoff.config.json` in the current working directory. You can customize:

- Service worker settings (autoRegister, autoUpdate, strategies)
- Feature toggles (offline, PWA, mutation queue, etc.)
- Build output directory and filename
- PWA install behavior
- IndexedDB database name and stores

See [Configuration Guide](/docs/configuration) for details.

## Troubleshooting

### Command not found

Always use `npx` to run the CLI:

```bash
npx @swoff/cli init
npx @swoff/cli generate
```

If you installed the package locally, make sure you're running from your project directory:

```bash
cd my-project
npx @swoff/cli init
```

### Validation errors

Run `npx @swoff/cli validate` to see specific errors in your configuration:

```bash
npx @swoff/cli validate
# Shows: Missing required fields: serviceWorker
```

### Generation fails

Check that your config is valid and the directories exist:

```bash
npx @swoff/cli validate && npx @swoff/cli generate
```

### No files generated

Check that `enabled` is `true` in your config:

```json
{
  "enabled": true
}
```

## Script Integration

Add Swoff commands to your `package.json`:

```json
{
  "scripts": {
    "swoff:init": "npx @swoff/cli init",
    "swoff:generate": "npx @swoff/cli generate",
    "swoff:validate": "npx @swoff/cli validate",
    "swoff:info": "npx @swoff/cli info",
    "swoff:clean": "npx @swoff/cli clean",
    "build": "npm run swoff:generate && your-build-command"
  }
}
```

Now you can run:

```bash
npm run swoff:init
npm run swoff:generate
npm run swoff:validate
npm run swoff:info
npm run swoff:clean
```
