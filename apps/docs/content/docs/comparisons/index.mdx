Swoff operates at the **browser infrastructure layer** — the Service Worker + `fetch` event — making it work with any backend, frontend, or rendering strategy. See [Ecosystem Compatibility](/docs/frameworks/ecosystem).

## Libraries Compared

| Library             | Category                  | Approach                           |
| ------------------- | ------------------------- | ---------------------------------- |
| **Swoff**           | Offline infra generator   | Config-driven code gen             |
| **Workbox**         | SW toolkit                | Build-time + runtime modules       |
| **vite-plugin-pwa** | SW (Vite)                 | Vite plugin wrapping Workbox       |
| **Serwist**         | SW (Next.js-first)        | Build-time + runtime modules       |
| **next-pwa**        | SW (Next.js)              | Workbox wrapper plugin             |
| **TanStack Query**  | Server state              | Runtime JS                         |
| **SWR**             | Server state              | Runtime JS                         |
| **RTK Query**       | Server state              | Runtime JS + Redux                 |
| **Apollo Client**   | GraphQL client            | Runtime JS                         |
| **RxDB**            | Client DB                 | Runtime JS                         |
| **ElectricSQL**     | Client DB (sync engine)   | Runtime + PGlite WASM              |
| **PowerSync**       | Client DB (sync engine)   | Runtime + SQLite                   |
| **TanStack DB**     | Client DB + offline-first | Runtime JS (differential dataflow) |

Generated files include a `DO NOT EDIT MANUALLY` header — edits are overwritten on the next `swoff generate`. Extend behavior via config, not by editing generated files. The `auth/check.ts` file is the one exception (intentionally user-editable).

Compare initialization side-by-side:

```ts
// Swoff — config-driven, any framework
import { initServiceWorker } from "./swoff/client-injector";
initServiceWorker();

// vite-plugin-pwa — Vite-only, wraps Workbox
import { registerSW } from "virtual:pwa-register";
registerSW();

// Serwist — Next.js–first
import { initialize } from "@serwist/next/browser";
initialize();

// next-pwa — Next.js config only
// no runtime init — configured in next.config.js
```

Swoff's `initServiceWorker` works in any framework with one config file. No `virtual:` imports, no build-plugin coupling.
