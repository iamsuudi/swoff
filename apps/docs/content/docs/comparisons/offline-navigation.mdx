When a user navigates offline, the browser shows "This site can't be reached" unless the Service Worker intercepts the navigation and serves a fallback. Swoff provides three navigation modes, a configurable multi-step fallback chain, HTML cache isolation, auto-prefetch on client-side navigation, per-route fallback rules, and smart background retry — framework-agnostic.

## How Swoff does it

**Three navigation modes** (set via `navigation.mode`):

| Mode        | Behavior                                                                                                                           | Use case                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `"spa"`     | Serves global fallback from precache (no runtime HTML caching for navigation). Default: `"/index.html"`.                           | Traditional SPAs                                                                   |
| `"default"` | No special nav handling — strategies handle all requests equally                                                                   | SSG sites                                                                          |
| `"ssr"`     | Checks HTML cache → per-route fallback → global fallback. Auto-prefetch on `pushState`/`replaceState`                              | Meta-frameworks (Next.js, Remix, Nuxt, SvelteKit, TanStack Start, Astro, HTMX)     |

**HTML cache isolation:** HTML responses are stored in their own cache container (`CACHE_NAME_RUNTIME_HTML`), separate from JSON, RSC payloads, JS, CSS, and images. Navigation requests read only from the HTML cache; non-navigation requests read from the main runtime cache. This prevents serving a non-HTML response during hard refresh without framework-specific logic.

**Ultimate fallback chain** (generated as `fromUltimateFallback` in the SW):

```
serveFromCache miss → _executeStrategy catch
  → startRetryLoop (background retry for navigation)
  → per-route fallback (from navigation rules, precache lookup)
  → global fallback (FALLBACK_PATH from precache)
  → inline 503 HTML page (guaranteed text/html)
```

The last step — inline `new Response(...)` with 503 — prevents the browser's native error page.

**Per-route fallback rules:**

```jsonc
"navigation": {
  "mode": "ssr",
  "rules": [
    { "match": "/blog/*", "fallback": "/blog-offline.html" },
  ]
}
```

Each rule's fallback page is auto-precached at install time.

**Smart navigation retry:** When navigation falls through to the inline 503, the SW starts a background retry loop (`intervalMs`, `maxRetries`). On success, the response is cached and a `swoff:navigation-online` custom event fires.

**Config-driven:** All of the above is configured through `swoff.config.json`. `swoff init` auto-detects the framework (Next.js, Remix, Astro, Nuxt, SvelteKit) and applies appropriate defaults.

## How competitors handle it

**next-pwa:** Creates a `NavigationRoute` via Workbox, auto-detects `pages/_offline.js`. Pages Router only — App Router support is unreliable. No HTML cache isolation, no auto-prefetch, no per-route fallback rules, no retry.

**@serwist/next:** Requires manual config in `next.config.ts` + `app/sw.ts`. Supports App Router, navigation preload, and per-strategy fallbacks. No HTML cache isolation — RSC payloads share the same cache slot as HTML. No auto-prefetch, no per-route rules, no retry.

**Workbox:** Uses `navigateFallback` on `GenerateSW` or `NavigationRoute` in `InjectManifest` mode. Single fallback — no per-route rules. No HTML cache isolation. No auto-prefetch. No retry.

**vite-plugin-pwa:** Wraps Workbox with Vite conveniences. Same limitations — single fallback, no HTML isolation, no auto-prefetch, no retry. Has meta-framework plugins (`@vite-pwa/nuxt`, `@vite-pwa/sveltekit`, etc.) but no Next.js integration.
