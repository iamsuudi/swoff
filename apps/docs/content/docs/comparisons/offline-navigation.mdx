When a user navigates offline, the browser shows "This site can't be reached" unless the Service Worker intercepts the navigation and serves a fallback. Swoff provides three navigation modes, a configurable multi-step fallback chain, HTML cache isolation, auto-prefetch on client-side navigation, per-route fallback rules, and smart background retry — framework-agnostic.

> See the [Navigation Caching guide](/docs/guides/navigation-caching) for Swoff's approach, config, and API. This page focuses on how other SW tools handle the same problem.

## How competitors handle it

**next-pwa:** Creates a `NavigationRoute` via Workbox, auto-detects `pages/_offline.js`. Pages Router only — App Router support is unreliable. No HTML cache isolation, no auto-prefetch, no per-route fallback rules, no retry.

**@serwist/next:** Requires manual config in `next.config.ts` + `app/sw.ts`. Supports App Router, navigation preload, and per-strategy fallbacks. No HTML cache isolation — RSC payloads share the same cache slot as HTML. No auto-prefetch, no per-route rules, no retry.

**Workbox:** Uses `navigateFallback` on `GenerateSW` or `NavigationRoute` in `InjectManifest` mode. Single fallback — no per-route rules. No HTML cache isolation. No auto-prefetch. No retry.

**vite-plugin-pwa:** Wraps Workbox with Vite conveniences. Same limitations — single fallback, no HTML isolation, no auto-prefetch, no retry. Has meta-framework plugins (`@vite-pwa/nuxt`, `@vite-pwa/sveltekit`, etc.) but no Next.js integration.
