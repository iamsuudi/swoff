Resource monitoring covers two concerns for offline-first apps: **network fetch timeout** (preventing stalled requests from blocking cache fallbacks) and **storage quota awareness** (notifying users before the browser evicts cached data).

> See the [Architecture: Observability](/docs/architecture/observability) for Swoff's approach. This page focuses on how other tools handle resource monitoring.

## How competitors handle it

**TanStack Query / SWR:** No SW-level fetch timeout. Storage estimation is entirely the developer's responsibility.

**Workbox:** Provides `NetworkTimeoutSeconds` per strategy, not global. No storage quota monitoring. Errors log to SW console, not surfaced to the window.

**Client DBs (RxDB, TanStack DB, ElectricSQL):** No fetch timeout — they don't intercept `fetch`. Storage management is handled by the local database engine.

**Vite-plugin-pwa:** Wraps Workbox — same limitations.
