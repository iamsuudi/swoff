## Two Completely Different Things

### PWA Install (User Experience)

"Installing" a PWA means creating a **shortcut** on the user's device:

```
User clicks "Install" → Browser creates shortcut → App opens in standalone window
```

This is **purely cosmetic**. It changes how the app looks (no browser UI), not what the app does.

### App Version Update (Technical)

Updating your app means replacing the **code** with a new version:

```
Developer releases v1.0.1 → Build generates new SW → User approves → New code runs
```

This is **functional**. It changes what the app does.

## Why People Confuse Them

Both use the word "install":

- PWA: "Install to home screen"
- App: "Install version 1.0.1"

But they're completely different:

| Aspect        | PWA Install      | App Version Update    |
| ------------- | ---------------- | --------------------- |
| **What**      | Creates shortcut | Replaces code         |
| **Trigger**   | User chooses     | Developer releases    |
| **Frequency** | Once per device  | Every release         |
| **Effect**    | UI changes       | Functionality changes |
| **Required**  | No               | Yes (for updates)     |
| **Offline**   | Doesn't help     | Makes it possible     |

## The Versioned App Flow

Swoff handles app updates through **versioned service workers**:

```
┌──────────────────────────────────────┐
│         Developer Releases           │
│                                      │
│  package.json: "version": "1.0.1"   │
│         ↓                            │
│  Build produces:                     │
│    - sw-v1.0.1.js                    │
│    - version.json                    │
└──────────────────────────────────────┘
              ↓
┌──────────────────────────────────────┐
│         User's Browser               │
│                                      │
│  App loads → Fetch version.json      │
│         ↓                            │
│  Same version? → Use current SW      │
│         ↓                            │
│  New version? → Show update prompt   │
│         ↓                            │
│  User approves → Register sw-v1.0.1  │
│         ↓                            │
│  New SW downloads → Activate → Reload │
└──────────────────────────────────────┘
```

## The PWA Install Flow

PWA install is separate and simpler:

```
┌──────────────────────────────────────┐
│         User's Device                │
│                                      │
│  User visits app → Browser detects   │
│  manifest.json → Shows install icon  │
│         ↓                            │
│  User clicks "Install"               │
│         ↓                            │
│  Shortcut created on home screen     │
│         ↓                            │
│  App opens in standalone window      │
└──────────────────────────────────────┘
```

## Can You Have One Without the Other?

### Offline App Without PWA Install

✅ **Yes** — app works offline, user accesses via browser bookmark

### PWA Install Without Offline

❌ **Possible but useless** — app "installs" but crashes without internet

### Versioned Updates Without PWA

✅ **Yes** — updates work regardless of install status

## Swoff's Approach

We separate these concerns completely:

1. **Versioned SW** handles code updates (core feature)
2. **PWA manifest** handles install prompt (optional extra)
3. **User consents** to both independently

:::info
Versioned SW covers your app shell (static assets, routes, client-side code). Data caching, mutation queuing, and sync are separate concerns handled by your app logic, not the SW version.
:::

```javascript
// Version update (automatic check, user consent required)
const manifest = await fetch("/version.json");
if (manifest.version !== currentVersion) {
  showUpdatePrompt(); // User must approve
}

// PWA install (user initiates)
window.deferredInstallPrompt?.prompt(); // User clicks "Install"
```

## Key Takeaway

> Installing a PWA doesn't update your app. Updating your app doesn't require PWA.

They're independent features. Swoff focuses on **versioned app updates** as the core, with PWA as a nice-to-have extra.
