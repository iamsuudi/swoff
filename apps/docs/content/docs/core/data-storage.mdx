## Two Tiers, Different Storage Needs

Swoff apps have different storage requirements based on the tier:

| API                | Capacity    | Data Type  | Sync  | Tier 1 (General)     | Tier 2 (Full Offline) |
| ------------------ | ----------- | ---------- | ----- | -------------------- | --------------------- |
| **Cache API**      | Unlimited\* | Requests   | Async | Cache read responses | App shell assets only |
| **IndexedDB**      | ~50MB+      | Structured | Async | Queue mutations      | Full app database     |
| **localStorage**   | ~5MB        | Strings    | Sync  | Settings, SW version | Settings, metadata    |
| **sessionStorage** | ~5MB        | Strings    | Sync  | Session state        | Session state         |

\*Limited by disk space and browser quota

## Tier 1: General Pattern (With Backend) [step]

### Cache API (Read Response Caching)

Cache GET/read request responses for offline access:

```javascript
// In your app, cache read responses
async function fetchWithCache(url) {
  const cache = await caches.open("read-cache-v1");

  // Try cache first
  const cached = await cache.match(url);
  if (cached) return cached.json();

  // Fetch and cache
  const response = await fetch(url);
  await cache.put(url, response.clone());
  return response.json();
}
```

### IndexedDB (Mutation Queue)

Queue mutations when offline, sync when back online:

```javascript
// Queue a mutation
async function queueMutation(mutation) {
  const db = await openDB("my-app", 1, {
    upgrade(db) {
      db.createObjectStore("mutation-queue", {
        keyPath: "id",
        autoIncrement: true,
      });
    },
  });
  const tx = db.transaction("mutation-queue", "readwrite");
  const store = tx.objectStore("mutation-queue");
  await store.add({ ...mutation, timestamp: Date.now() });
}

// Sync when online
async function syncQueue() {
  const db = await openDB("my-app", 1);
  const tx = db.transaction("mutation-queue", "readonly");
  const store = tx.objectStore("mutation-queue");
  const mutations = await store.getAll();

  for (const mutation of mutations) {
    await fetch("/api/mutate", {
      method: "POST",
      body: JSON.stringify(mutation),
    });
    // Remove from queue after successful sync
  }
}
```

### localStorage (Metadata)

For small config values:

```javascript
// Settings
localStorage.setItem("theme", "dark");
const theme = localStorage.getItem("theme");

// Version tracking
localStorage.setItem("swRegisteredVersion", "1.0.0");
```

### sessionStorage (Session State)

For temporary state (cleared on tab close):

```javascript
// Cleared when tab closes
sessionStorage.setItem("current-view", "list");
const view = sessionStorage.getItem("current-view");
```

## Tier 2: Full Offline (Budget Manager Pattern) [step]

### IndexedDB (Full Database)

Use IndexedDB as your **complete database** (no backend):

```javascript
// Open database
function openDB() {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open("my-app", 1);

    request.onupgradeneeded = (e) => {
      const db = e.target.result;
      const store = db.createObjectStore("todos", { keyPath: "id" });
      store.createIndex("by-date", "date");
    };

    request.onsuccess = (e) => resolve(e.target.result);
    request.onerror = (e) => reject(e.target.error);
  });
}

// Add item
async function addTodo(todo) {
  const db = await openDB();
  const tx = db.transaction("todos", "readwrite");
  const store = tx.objectStore("todos");
  await new Promise((resolve) => {
    const request = store.add(todo);
    request.onsuccess = resolve;
  });
}
```

### Cache API (App Shell Only)

Used by Service Worker for app shell caching:

```javascript
// In SW
const cache = await caches.open("my-app-v1");
await cache.addAll(["/", "/index.html", "/app.js"]);
```

## Storage Quota

Check available storage:

```javascript
const estimate = await navigator.storage.estimate();
console.log(`Using ${estimate.usage} of ${estimate.quota} bytes`);
```

## Swoff's Recommendation

### Tier 1 (Most Apps)

```
┌─────────────────────────────────────┐
│         Tier 1 Storage Strategy      │
│                                     │
│  Cache API                          │
│  - Cache read request responses     │
│  - Offline read access              │
│                                     │
│  IndexedDB                          │
│  - Queue mutations when offline     │
│  - Sync when back online            │
│                                     │
│  localStorage                       │
│  - UI preferences (theme, language) │
│  - SW version tracking              │
│                                     │
│  sessionStorage                     │
│  - Current route state              │
│  - Form draft data                  │
└─────────────────────────────────────┘
```

### Tier 2 (Budget Manager Pattern)

```
┌─────────────────────────────────────┐
│         Tier 2 Storage Strategy      │
│                                     │
│  IndexedDB (Full Database)          │
│  - All app data (todos, users)      │
│  - Large datasets                   │
│  - No backend needed                │
│                                     │
│  Cache API (via SW)                 │
│  - App shell assets only            │
│                                     │
│  localStorage                       │
│  - Settings, metadata              │
└─────────────────────────────────────┘
```
