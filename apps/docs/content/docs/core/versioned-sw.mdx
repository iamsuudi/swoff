## The Problem

Traditional SW registration uses a fixed path like `/sw.js`. The browser automatically downloads and activates new versions on reload — dangerous if the update has breaking changes.

## Swoff's Solution: Versioned Filenames

Instead of `/sw.js`, we use `/sw-v1.0.0.js`, `/sw-v1.0.1.js`, etc. Each version is a unique file that the browser only loads when you tell it to.

```
dist/
├── sw-v1.0.0.js      ← Version 1.0.0
├── sw-v1.0.1.js      ← Version 1.0.1
└── version.json      ← Version manifest
```

## How It Works

### 1. Version from package.json

```json
{ "name": "my-app", "version": "1.0.0" }
```

### 2. Build Generates Versioned SW

A build script reads the version, replaces placeholders in the SW template, and outputs the versioned file plus `version.json`:

```javascript
// generate-sw.js
const pkg = JSON.parse(readFileSync("package.json", "utf8"));
const template = readFileSync("src/sw-template.js", "utf8");

let sw = template
  .replace("// [[CACHE_NAME]]", `const CACHE_NAME = 'sw-v${pkg.version}'`)
  .replace("// [[ASSETS_LIST]]", `const ASSETS = ['/', '/index.html']`);

writeFileSync(`dist/sw-v${pkg.version}.js`, sw);
writeFileSync(
  "dist/version.json",
  JSON.stringify({
    version: pkg.version,
    minSupportedVersion: pkg.minSupportedVersion || pkg.version,
    generatedAt: new Date().toISOString(),
  }),
);
```

### 3. Client Checks version.json

```javascript
async function checkForUpdate() {
  const response = await fetch("/version.json");
  return response.json();
}

async function registerSpecificVersion(version) {
  const registration = await navigator.serviceWorker.register(
    `/sw-v${version}.js`,
  );
  localStorage.setItem("swRegisteredVersion", version);
  return registration;
}
```

## Update Flow

```
User opens app
    ↓
Fetch /version.json → Compare with localStorage['swRegisteredVersion']
    ↓
Same version? → Use existing SW
New version? → Fire 'sw-update-available' event → Show prompt
    ↓
User approves → Register new SW → Downloads assets → SKIP_WAITING → Reload
```

## Version Manifest

```json
{
  "version": "1.0.1",
  "minSupportedVersion": "1.0.0",
  "generatedAt": "2024-01-15T10:30:00.000Z"
}
```

| Field                 | Purpose                                           |
| --------------------- | ------------------------------------------------- |
| `version`             | SemVer version string of this build               |
| `minSupportedVersion` | Minimum version users must have (enforced update) |
| `generatedAt`         | ISO timestamp of build                            |

## Update Consent Flow

Users explicitly approve updates. The flow: `idle → available → downloading → reload`.

### Update Prompt Component

```typescript
function UpdatePrompt() {
  const [status, setStatus] = useState<'idle' | 'available' | 'downloading'>('idle');

  useEffect(() => {
    window.addEventListener('sw-update-available', () => setStatus('available'));
  }, []);

  if (status === 'idle') return null;

  return (
    <div>
      <p>Update available!</p>
      <button onClick={acceptUpdate}>Update</button>
    </div>
  );
}
```

### Minimum Supported Version (Forced Updates)

When releasing critical updates, set `minSupportedVersion` in `package.json`:

```json
{ "version": "1.0.5", "minSupportedVersion": "1.0.5" }
```

If the user's registered version is less than `minSupportedVersion`, the update is mandatory — full-screen overlay with no dismiss option. Otherwise, it's optional (standard bottom-sheet).

**Example**: v1.0.5 is released with `minSupportedVersion: "1.0.5"` (security fix). v1.0.6 follows with `minSupportedVersion: "1.0.5"` (feature). A user on v1.0.4 visiting during v1.0.6 is **forced to update** because 1.0.4 < 1.0.5.

### Session Dismissal

Suppress the update dialog for the current session:

```typescript
function dismissUpdate() {
  sessionStorage.setItem("sw-dismissed-update", "true");
}
```

### Events and Window Properties

| Event                 | Purpose              |
| --------------------- | -------------------- |
| `sw-update-available` | New version detected |
| `sw-progress`         | Download progress    |
| `sw-ready`            | SW active            |

```typescript
interface Window {
  latestSWVersion?: string;
  currentSWVersion?: string;
  swMinSupportedVersion?: string;
}
```

## SW Template

```javascript
// src/sw-template.js
// [[CACHE_NAME]]
// [[ASSETS_LIST]]

self.addEventListener("install", (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => cache.addAll(ASSETS)),
  );
});

self.addEventListener("fetch", (event) => {
  if (event.request.method !== "GET") return;
  event.respondWith(
    caches
      .match(event.request)
      .then(
        (cached) =>
          cached ||
          (event.request.mode === "navigate"
            ? caches.match("/index.html")
            : fetch(event.request)),
      ),
  );
});

self.addEventListener("activate", (event) => {
  event.waitUntil(
    caches
      .keys()
      .then((keys) =>
        Promise.all(
          keys.filter((k) => k !== CACHE_NAME).map((k) => caches.delete(k)),
        ),
      ),
  );
});
```

:::info
This template handles **app shell caching**. For caching dynamic read responses, see [Offline-First Architecture](/docs/core/offline-architecture#storage-strategy).
:::

## Benefits

1. **No silent updates** — users explicitly approve
2. **Rollback possible** — re-register the old version
3. **Clear versioning** — filename shows exact version
4. **Browser agnostic** — works in all browsers with SW support
