# Svelte

Swoff works with any Svelte-based project. Svelte adapters (stores) are not yet generated by the CLI, but all window events are available for manual integration. See the [Blueprint](/docs/framework-adapters/blueprint) to create stores for your project.

## Config per flavor

| Setting               | Svelte + Vite   | SvelteKit |
| --------------------- | --------------- | --------- |
| `build.outputDir`     | `"dist"`        | `"build"` |
| `build.swFilename`    | `"sw"`          | `"sw"`    |
| `navigation.mode`     | `"spa"`         | `"ssr"`   |
| `navigation.fallback` | `"/index.html"` | `"/"`     |
| `navigation.preload`  | `true`          | `true`    |

SvelteKit uses SSR mode because it renders on the server. Set `navigation.mode` to `"ssr"` to enable runtime-html caching for server-rendered routes.

## Entry point

```svelte
<script>
  import { onMount } from "svelte";
  import { initServiceWorker } from "$lib/swoff/client-injector";

  onMount(() => { initServiceWorker(); });
</script>
```

For SvelteKit, call `initServiceWorker` in `+layout.svelte` inside `onMount`.

## Window events (no adapter needed)

The SW broadcasts lifecycle events as `window` custom events. Listen for them directly in any Svelte component using `writable` stores or `onMount`:

```svelte
<script>
  import { onMount, onDestroy } from "svelte";
  import { writable } from "svelte/store";

  export let swReady = writable(false);

  function onSwReady() { $swReady = true; }

  onMount(() => {
    window.addEventListener("sw-ready", onSwReady);
  });

  onDestroy(() => {
    window.removeEventListener("sw-ready", onSwReady);
  });
</script>
```

All [Blueprint events](/docs/framework-adapters/blueprint#window-events) work the same way — `sw-update-available`, `sw-auth-state-change`, `cache-invalidated`, `mutation-queue-changed`, and more.

## Build script

Run the SW generator after your build:

```bash
node swoff/sw/generator.js
```

Or add it to `package.json`:

```json
{
  "scripts": {
    "build": "your-build && node swoff/sw/generator.js"
  }
}
```

SvelteKit outputs to `build/` by default. The SW generator reads `build.outputDir` from config and writes the versioned SW there automatically.

## Adapters (stores)

Once you create stores via the [Blueprint](/docs/framework-adapters/blueprint), import them like:

```ts
import { useCachedFetch } from "./swoff/adapters/useCachedFetch";
```

The naming convention is the same across all frameworks — the adapter layer maps window events to your framework's reactive system. The [Blueprint](/docs/framework-adapters/blueprint) shows the complete event map and a template for creating Svelte stores.
