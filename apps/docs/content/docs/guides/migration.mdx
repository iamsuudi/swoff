## Migration Guide

Switching to Swoff is straightforward — it's code you copy, not an npm dependency. Here's how to migrate from common setups.

## From Workbox

Workbox is popular but adds bundle weight and library updates. Swoff gives you simpler, owned code.

### Key Differences

| Aspect | Workbox | Swoff |
|--------|---------|-------|
| Installation | npm install | Copy files |
| Updates | npm update | Replace files |
| Versioning | Automatic (browser) | Your package.json |
| Customization | Config options | Edit code directly |
| Bundle impact | ~30KB+ | ~0KB (copy-paste) |

### Migration Steps

#### 1. Extract Your Caching Strategy

Workbox routes define what's cached. Map them to Swoff:

```javascript
// Workbox (before)
import { registerRoute } from 'workbox-routing';
registerRoute(
  ({ url }) => url.pathname.startsWith('/api/'),
  new NetworkFirst({ cacheName: 'api' })
);

// Swoff equivalent (in sw-template.js fetch handler)
async function networkFirst(event, request) {
  const cached = await runtimeCache.match(request);
  if (cached) return cached;
  return fetch(request);
}
```

#### 2. Replace Workbox Strategies

| Workbox Strategy | Swoff Equivalent |
|------------------|------------------|
| `CacheFirst` | Default in fetch handler |
| `NetworkFirst` | Check fetch, fallback to cache |
| `StaleWhileRevalidate` | Set `X-SW-Stale: true` header |
| `NetworkOnly` | Set `X-SW-Cache-Strategy: mutation` |
| `CacheOnly` | Match cache only, no network |

#### 3. Move Workbox Config to Swoff

```javascript
// workbox-config.js (before)
module.exports = {
  globDirectory: 'dist',
  globPatterns: ['**/*.{js,css,html,png}'],
  swDest: 'dist/sw.js',
};

// Swoff: swoff/sw-generator.js (create this file)
import { readFileSync, writeFileSync } from "fs";
import { join, dirname } from "path";
import { fileURLToPath } from "url";

const __dirname = dirname(fileURLToPath(import.meta.url));
const pkg = JSON.parse(readFileSync(join(__dirname, "package.json"), "utf8"));
const template = readFileSync(join(__dirname, "swoff/sw-template.js"), "utf8");

const sw = template
  .replace('// [[CACHE_NAME]]', `CACHE_NAME = 'sw-v${pkg.version}'`)
  .replace('// [[ASSETS_LIST]]', `ASSETS_TO_CACHE = ['/', '/index.html']`);

writeFileSync(join(__dirname, "dist", `sw-v${pkg.version}.js`), sw);
writeFileSync(join(__dirname, "dist", "version.json"), JSON.stringify({
  version: pkg.version,
  minSupportedVersion: pkg.minSupportedVersion || "0.0.0",
  generatedAt: new Date().toISOString(),
}));
```

#### 4. Update Client Registration

```javascript
// Before (Workbox)
import {Workbox} from 'workbox-window';
const wb = new Workbox('/sw.js');
wb.register();

// After (Swoff) - swoff/sw-injector.js
async function initServiceWorker() {
  if (!("serviceWorker" in navigator)) return;
  const manifest = await fetch("/version.json").then(r => r.json());
  const currentVersion = localStorage.getItem("swRegisteredVersion");

  if (currentVersion !== manifest.version) {
    await navigator.serviceWorker.register(`/sw-v${manifest.version}.js`);
    localStorage.setItem("swRegisteredVersion", manifest.version);
  }
}
initServiceWorker();
```

#### 5. Remove Workbox

```bash
npm uninstall workbox-precaching workbox-routing workbox-strategies workbox-cache-expiration
```

## From Other PWA Libraries

### From PWA Builder (Microsoft)

```bash
# PWA Builder generates service-worker.js
# Swoff: copy sw-template.js instead
cp swoff/sw-template.js dist/sw.js
```

Key changes:
- Remove PWA Builder's `configurePreCaching` 
- Add your own `ASSETS_TO_CACHE` in Swoff
- Use Swoff's versioned SW instead of auto-generated

### From Vite PWA Plugin

```javascript
// vite.config.js (before)
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    VitePWA({
      registerType: 'autoUpdate',
      manifest: { ... },
      workbox: { ... },
    }),
  ],
});
```

Migration:
1. Remove `vite-plugin-pwa` from config
2. Add Swoff's build script to package.json
3. Add Swoff's client registration to your app

### From Offline.js / Service Worker Cache

If you have custom SW code without a library:

```javascript
// Before (custom sw.js)
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request).then(response => response || fetch(event.request))
  );
});

// After: Replace with Swoff's sw-template.js
// It handles caching better and adds versioning
```

## Adopting in Existing Apps

### Step 1: Add Swoff Without Breaking

Add the 3 core files alongside existing setup:

```
your-project/
├── swoff/
│   ├── sw-template.js    # New service worker
│   ├── sw-generator.js   # Build script
│   └── sw-injector.js    # Registration
└── (existing files unchanged)
```

### Step 2: Test Side by Side

1. Generate your Swoff SW: `npm run build`
2. Register it alongside existing SW
3. Verify caching works for static assets

### Step 3: Migrate Caching Logic

Move caching behavior from existing SW to Swoff:

```javascript
// Your old SW behavior
cache.addAll(['/', '/index.html', '/styles.css']);

// Swoff: update sw-template.js
ASSETS_TO_CACHE = ['/', '/index.html', '/styles.css', '/app.js'];
```

### Step 4: Remove Old SW

Once Swoff works:
1. Delete old service worker file
2. Clear old cache: `caches.keys().then(keys => keys.forEach(k => caches.delete(k)))`
3. Update version in package.json to force new SW

## Concept Mapping

| Workbox | Swoff |
|---------|-------|
| `registerRoute()` | Fetch handler in sw-template.js |
| `precacheAndRoute()` | ASSETS_TO_CACHE in sw-template.js |
| `CacheFirst` / `NetworkFirst` | Custom fetch functions |
| `workbox.core.skipWaiting()` | `self.skipWaiting()` |
| `workbox.core.clientsClaim()` | Automatic on activate |
| `ExpirationPlugin` | Manual cache trimming |
| `BackgroundSyncPlugin` | Swoff's Background Sync (advanced) |

## Common Migration Issues

### Issue: Duplicate Caching

Both SWs try to cache the same resources.

**Fix**: Disable old SW's caching before removing it:

```javascript
// In old SW
self.addEventListener('fetch', event => {
  event.respondWith(fetch(event.request)); // Disable cache
});
```

### Issue: Version Conflicts

Old cached assets conflict with new SW.

**Fix**: Swoff handles this via versioning. Make sure to:
1. Increment version in package.json
2. Clear old caches in activate handler

### Issue: Scope Mismatch

New SW controls fewer routes than old SW.

**Fix**: Ensure SW file is at root of project:

```
your-project/
├── index.html
├── sw-v1.0.0.js    ← At root, controls entire domain
└── js/
    └── app.js
```
