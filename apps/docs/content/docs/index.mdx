Swoff generates offline-first infrastructure for your web app — the CLI produces a Service Worker and client code from a single config file, with zero runtime dependencies. You own every generated file; no library version conflicts, no hidden breakage.

```bash
npx @swoff/cli init --framework vanilla
npx @swoff/cli generate
```

## What Swoff does

Swoff works at the browser infrastructure layer — the Service Worker intercepts `fetch` events, caches HTTP responses, replays offline mutations, and keeps tabs in sync. This is below the application and data-fetching layers, so it composes with anything: React, Vue, Svelte, HTMX, or vanilla JS — and any backend (Laravel, Django, Rails, Go, PHP).

## What Swoff does not do

- **Not a runtime library** — the CLI generates code you own, zero KB in your bundle
- **Not a backend framework** — bring your own server, no vendor lock-in
- **Not an SSR framework** — focuses on browser APIs after the page loads

## Why this approach

Most offline-capable tools either lock you into a framework (TanStack Query), handle only the Service Worker (Workbox, Serwist), or force a dual-database architecture (RxDB, TanStack DB). Operating at the `fetch` event layer lets Swoff serve any framework, any rendering strategy, and any backend — with the generated code as the only dependency.
