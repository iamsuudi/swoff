Swoff is a **code generation toolchain** for offline-first, installable PWAs — not a runtime library. It generates an auditable service worker and client code from a single config file, with zero runtime dependencies.

- You only need Node.js to run the CLI and build script — no `package.json`, no `npm install` in your project
- The output is plain JavaScript you serve as a static asset
- Works with any backend (Laravel, Django, Rails, Go, PHP) and any frontend (React, Vue, Svelte, HTMX, vanilla)

```bash
# Get started with any project
npx @swoff/cli init --framework vanilla && npx @swoff/cli generate
```

## What Swoff is NOT

- **Not a runtime npm package** — the CLI generates code you own, zero KB in your bundle
- **Not a backend framework** — bring your own Go, Node.js, Python, PHP
- **Not tied to any fullstack framework** — purely client-side, framework-agnostic
- **Not an SSR framework** — we focus on browser APIs after the page loads

:::warning
Swoff focuses on **client-side browser APIs** (offline app shell, data caching, sync). Your backend is your responsibility.
:::

## Why this approach

Most tools either:
- Lock you into a framework (TanStack Query, Apollo Client)
- Only handle the SW (Workbox, Serwist)
- Force a dual-database architecture (RxDB, TanStack DB)

Swoff operates at the `fetch` event layer — below the application and data-fetching layers. This makes it smaller, simpler, and composable with anything.
