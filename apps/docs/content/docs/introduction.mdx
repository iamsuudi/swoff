## What is Swoff?

Swoff is a zero-dependency blueprint for building offline-first, versioned web apps that feel native.

> We provide code and architecture, not dependencies.

Swoff is not a traditional library. You copy our service worker, hooks, and utilities into your project, then modify them to fit your needs. No waiting for library updates, no bundle bloat.

## Modular by Design

Swoff is a **toolbox**, not a framework. Every feature is a file you copy into your project and own.

## Configuration-First Development

Swoff now offers two approaches to service worker development:

### 1. Configuration-Driven (Recommended)

Configure Swoff behavior through a simple JSON file:

```json
// swoff.config.json
{
  "$schema": "https://swoff.ai/schema/v1.json",
  "enabled": true,
  "version": "from-package",
  "serviceWorker": {
    "defaultStrategy": "cache-first",
    "strategies": {
      "/api/*": "network-first",
      "/static/*": "cache-first"
    }
  },
  "features": {
    "offlineReads": true,
    "mutationQueue": true
  }
}
```

**Benefits**: Easy setup, automatic optimization, no custom code required.

### 2. Custom Code Mode

For complete control, write your own service worker:

```json
// swoff.config.json
{
  "enabled": false
}
```

**Benefits**: Full control over every aspect of service worker behavior.

## Quick Start with Configuration

1. **Copy configuration**:
   ```bash
   cp examples/shared/swoff.config.example.json swoff.config.json
   ```

2. **Customize your JSON config** for your app's needs

3. **Generate service worker**:
   ```bash
   node examples/shared/sw-generator.js
   ```

4. **Register the generated service worker** in your application

For detailed configuration options, see the [Configuration Guide](/docs/configuration/getting-started).
