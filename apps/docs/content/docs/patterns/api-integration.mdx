**Prerequisites:** You have the SW template set up (see [SW Template](/docs/patterns/sw-template)). This pattern shows how to mark client requests so the SW can distinguish reads from mutations, and how to tag cached responses for selective invalidation.

## How It Works

The SW checks two request headers:

| Header | Value | SW behavior |
|---|---|---|
| `X-SW-Cache-Strategy` | `read` | Cache the response, serve from cache on repeat requests |
| `X-SW-Cache-Strategy` | `mutation` or absent | Let the request pass through to the server, no caching |
| `X-SW-Cache-Tags` | `todos,user:1` | Index the cached response under these tags for later invalidation |
| `X-SW-Stale` | `true` | Serve cached immediately, refresh in background (stale-while-revalidate) |

If the strategy header is absent, the SW falls back to method-based heuristic: GET/HEAD are reads, everything else is a mutation.

## Fetch Wrapper

```js title="swoff/fetch-wrapper.js"
const inFlightRequests = new Map();

/**
 * Fetch with cache strategy, optional tags, stale-while-revalidate, and query dedup.
 * @param {Request|string} input
 * @param {object} [options]
 * @param {string} [options.strategy] - "read" | "mutation" (auto-detected by method)
 * @param {string[]} [options.tags] - Cache tags for invalidation (e.g., ["todos"])
 * @param {boolean} [options.staleWhileRevalidate] - Serve cached, refresh in background
 */
export async function fetchWithCache(input, options = {}) {
  const headers = new Headers(options.headers);
  const method = options.method || "GET";

  if (!headers.has("X-SW-Cache-Strategy")) {
    headers.set(
      "X-SW-Cache-Strategy",
      method === "GET" || method === "HEAD" ? "read" : "mutation",
    );
  }

  if (options.staleWhileRevalidate) {
    headers.set("X-SW-Stale", "true");
  }

  if (options.tags && options.tags.length > 0) {
    headers.set("X-SW-Cache-Tags", options.tags.join(","));
  }

  // Query deduplication: collapse concurrent GET requests for the same URL
  if (method === "GET" || method === "HEAD") {
    const url = typeof input === "string" ? input : input.url;
    if (inFlightRequests.has(url)) {
      return inFlightRequests.get(url).then((r) => r.clone());
    }
    const promise = fetch(input, { ...options, headers }).finally(() => {
      inFlightRequests.delete(url);
    });
    inFlightRequests.set(url, promise);
    return promise;
  }

  return fetch(input, { ...options, headers });
}
```

Defaults to `read` for GET/HEAD and `mutation` for everything else. Override by passing the header explicitly.

## Cache Invalidation

After a mutation syncs to the server, cached GET responses become stale. Call `invalidateByTag` to flush them:

```js title="swoff/cache.js"
const CACHE_TAG_DB = "swoff-cache-tags";
const CACHE_TAG_STORE = "tags";

/**
 * Invalidate all cached responses tagged with the given tag.
 * Clears the SW runtime cache and dispatches "cache-invalidated" on window.
 * @param {string} tag - Cache tag to invalidate (e.g., "todos")
 */
export async function invalidateByTag(tag) {
  if (!navigator.serviceWorker?.controller) return;

  // Tell SW to clear cached responses with this tag
  navigator.serviceWorker.controller.postMessage({
    type: "INVALIDATE_TAG",
    tag,
  });

  // Notify framework adapters
  window.dispatchEvent(
    new CustomEvent("cache-invalidated", { detail: { tags: [tag] } }),
  );
}

/**
 * Invalidate multiple tags at once.
 * @param {string[]} tags
 */
export async function invalidateByTags(tags) {
  for (const tag of tags) {
    await invalidateByTag(tag);
  }
}
```

The SW receives the `INVALIDATE_TAG` message, looks up all cached URLs indexed under that tag, deletes them from the runtime cache, and broadcasts `TAG_INVALIDATED` back. See [SW Template](/docs/patterns/sw-template#4-message--skip-waiting--cache-invalidation) for the SW-side handler.

## REST API

```javascript
import { fetchWithCache } from "./swoff/fetch-wrapper.js";

// GET — cached with tag for later invalidation
const todos = await fetchWithCache("/api/todos", {
  tags: ["todos"],
}).then((r) => r.json());

// GET single item
const todo = await fetchWithCache("/api/todos/1", {
  tags: ["todos", "todo:1"],
}).then((r) => r.json());

// POST search — override to read with tag
const results = await fetchWithCache("/api/search", {
  method: "POST",
  headers: { "X-SW-Cache-Strategy": "read" },
  tags: ["search"],
  body: JSON.stringify({ query: "hello" }),
}).then((r) => r.json());

// POST create — mutation, passes through to server
await fetchWithCache("/api/todos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "New task" }),
});
```

## GraphQL

Queries and mutations both POST to one endpoint. Inspect the operation string to set the right strategy and tags:

```javascript
import { fetchWithCache } from "./swoff/fetch-wrapper.js";

async function graphql(query, variables = {}) {
  const isMutation = query.trimStart().startsWith("mutation");
  const operationName = extractOperationName(query);

  const data = await fetchWithCache("/api/graphql", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-SW-Cache-Strategy": isMutation ? "mutation" : "read",
    },
    tags: isMutation ? undefined : [operationName],
    body: JSON.stringify({ query, variables }),
  }).then((r) => r.json());

  if (data.errors) throw new Error(data.errors[0].message);
  return data.data;
}

function extractOperationName(query) {
  const match = query.trim().match(/^(query|mutation)\s+(\w+)/);
  return match ? match[2] : "unknown";
}

// Query — cached with tag "todos", invalidatable
const user = await graphql(`query todos { todos { id title } }`);

// Mutation — reaches the server, triggers invalidation
const updated = await graphql(
  `mutation { updateUser(id: 1, name: "Alice") { name } }`,
);
```

## Invalidation Strategy

| After this mutation | Invalidate these tags |
|---|---|
| `POST /api/todos` | `["todos"]` |
| `PUT /api/todos/:id` | `["todos", "todo:{id}"]` |
| `DELETE /api/todos/:id` | `["todos", "todo:{id}"]` |
| `POST /api/todos/:id/comments` | `["todos", "todo:{id}", "comments"]` |

A helper for tagging mutation-related cache invalidation:

```javascript
function invalidationTags(url, method, body) {
  const urlObj = new URL(url, location.origin);
  const parts = urlObj.pathname.split("/").filter(Boolean);

  // /api/todos → ["todos"]
  // /api/todos/42 → ["todos", "todo:42"]
  // /api/todos/42/comments → ["todos", "todo:42", "comments"]
  const tags = [];
  for (let i = 0; i < parts.length; i++) {
    if (parts[i] === "api") continue;
    if (i > 0 && /^\d+$/.test(parts[i])) {
      tags.push(`${parts[i - 1]}:${parts[i]}`);
    } else if (!/^\d+$/.test(parts[i])) {
      tags.push(parts[i]);
    }
  }
  return tags;
}
```

## Stale-While-Revalidate

Serve cached data instantly, refresh in the background. The user always sees data immediately if it's been fetched before.

### Usage

```javascript
// Stale-while-revalidate: serve cached, refresh in background
const todos = await fetchWithCache("/api/todos", {
  tags: ["todos"],
  staleWhileRevalidate: true,
}).then((r) => r.json());

// Same API, without stale-while-revalidate (cache-first default)
const fresh = await fetchWithCache("/api/todos/1", {
  tags: ["todos", "todo:1"],
}).then((r) => r.json());
```

When `staleWhileRevalidate: true` is set, the SW:
1. Returns the cached response immediately (if available)
2. Fetches fresh data from the network in the background
3. Updates the cache with fresh data for next time

If no cached response exists yet, the SW fetches from network and caches normally.

### When to Use

| Strategy | Best For | Trade-off |
|---|---|---|
| Cache-First (default) | Static data, navigation, assets | User sees slightly stale data until SW refreshes |
| Stale-While-Revalidate | Frequently accessed API data | Extra background request on every read |
| Network-First | Real-time data, forms | Slower when offline, no stale data risk |

## Query Deduplication

When two components request the same URL concurrently, the second caller reuses the in-flight request instead of firing a duplicate.

### How It Works

```javascript
// Component A and B both mount and request the same data
// Without dedup: two fetch requests to the SW
// With dedup: one fetch request, both get the response

const wrapper = await fetchWithCache("/api/todos", { tags: ["todos"] });
const details = await fetchWithCache("/api/todos", { tags: ["todos"] });
// Only one network request is made — the second gets a clone of the first response
```

The dedup map tracks in-flight GET requests by URL. When a request completes, its entry is removed so subsequent calls go to the network (or SW cache). The cloned response ensures both callers can consume the body independently.
